# Tracks — one-off plans that are not numbered phases

These are working plans that sit outside the numbered product roadmap
([`../README.md`](../../phases/README.md)) and outside the AI competence program
([`../ai-agent/README.md`](../../phases/ai-agent/README.md)). They live here so they are not lost,
**not** because they are scheduled.

> **Read the Status column before the document.** The folder now holds two kinds of thing. The table
> below is the original set: two finished, one deferred, one in progress, three unscheduled proposals
> (one re-derives an abandoned never-merged branch; one opens with verified defects in shipped code
> rather than with a proposal; one is a captured cross-browser settings feature-gap list), and one
> superseded proposal that its own text flags as a security regression unless every hardening measure
> lands together. Below that is an index of a **second, separate set** that no longer lives in this
> folder: the 25 competitor-parity tracks, moved to [`../parities/`](../parities/). The table is kept
> here because it is the only place their Scope is summarized side by side.
> Nothing in this folder is committed roadmap. A track earns a phase row by being promoted into a
> `phase-*.md` file or an ADR — until then it is a written idea with an owner's name on it, not a plan of
> record.

## Competitor-parity tracks (2026-09-01/02) — now in [`../parities/`](../parities/)

**All 25 are 📋 Proposed — not approved, not scheduled.** Each one reads a rival's checked-out source
under `.junk/<rival>/` plus its [`../versus/`](../versus/)`tepegoz-vs-<rival>.md` comparison, then maps only the
capabilities that are _genuinely good and genuinely missing here_ to a Tepegöz-conformant approach, a
suggested phase/ADR home, and a draft DoD. They were produced by running
[`../../prompts/rival-agent-parity-track.md`](../../prompts/rival-agent-parity-track.md) once per rival.

Read these four things before treating any row as a plan:

- **Nothing here is roadmap.** v1 is five phases ([`../README.md`](../../phases/README.md#v1-ship-line-owner-decision-2026-08-21)); these are ~80 proposed workstreams against a program where **no AI phase reads ✅**. The count is a measure of surveyed surface, not of committed work.
- **Every track has a `Ground rules — parity, not imitation` section** naming what it _deliberately did not match_ and the standing ADR that forbids it. Across the set the recurring rejections are: `execute_js`/terminal/code-exec tools (ADR-0026 measured-refuted + ADR-0029 DevTools user-only), screenshot-every-step vision (ADR-0008 + the `ai-agent` "Never" list), CAPTCHA solving (ADR-0039 Human Handoff), unauthenticated local control ports and outward CDP servers (ADR-0006/0007 single PEP), and vendor agent SDKs (the "Never" list's "port techniques, never adopt").
- **A thin track is a real result.** Where a rival is a different product category the honest answer was a short document, not a padded one — Lightpanda closes with **zero** workstreams, and Min, LaVague, Nova Act, AgentQL and Crawl4AI with one each.
- **Two accuracy corrections propagated through the set** and should be honoured by anything built from them: `@tepegoz/notary` is written and unit-tested but **`apps/desktop` imports it nowhere** — no run produces a Replay Receipt today ([ADR-0030](../../docs/adr/0030-notary-service.md) says so itself); and S10 vision **ships inert** — the Reactor's `captureVision` callback has no production caller.

## Where these rows now appear in the roadmap (2026-09-02)

The workstreams above whose stated home is a **product phase** have been cross-referenced into
[`../product/`](../product/), following the same convention
[`browser-settings-feature-gap.md`](browser-settings-feature-gap.md) already used: one `- [ ]` row in the
owning section, naming the nearest existing behaviour and citing the track and workstream it came from.

**This does not promote anything to roadmap.** Every folded row is unchecked and carries "Captured, not
scheduled" (or an equivalent hedge); the rule at the top of this file still holds — a track earns a real
phase row by being promoted into a `phase-*.md` DoD or an ADR, and none of these have been. What the
fold buys is that the next session opening Phase 1b, 3, 6, 7 or 9 sees the finding **in the file it is
already reading**, instead of having to know this folder exists.

Two things were written into the phases as **defects rather than proposals**, because that is what the
sources verified them to be: the missing destination validation on agent-driven outbound fetch
([`../product/phase-2-adapters-safe-browsing.md`](../../phases/product/phase-2-adapters-safe-browsing.md) L10 —
found independently by `browserless` P1 and `librechat` P2), and the 11 omnibox defects recorded under the
already-ticked Phase 1a omnibox row
([`../product/phase-1a-walking-skeleton-mvp.md`](../../phases/product/phase-1a-walking-skeleton-mvp.md)).

**As of 2026-09-02 the fold is complete in both directions:** every leaf workstream in all 25 tracks now
has a citation in a phase file — the product-homed ones in [`../product/`](../product/), and the rest in
[`../ai-agent/`](../../phases/ai-agent/README.md), which took the larger share. They arrived as new
sections rather than scattered rows, so each is readable as one body of work: **S2 PR7** (perception reach
— the most-cited gap in the whole survey), **S6 PR10** (credential broker, gated mutating fetch, read-only
diagnostics, the `edit` HITL answer), **S7 PR7** (context economy and caching), **S8 PR9** (console
affordances), **S9 PR7** (skills that declare tools), plus single sections in S1, S3, S5, S10, S11 and S12.
A mechanical audit over track headings → phase citations reports zero unhomed leaves; the umbrella headings
(`P3`, `P7`, `P9` and friends) carry no content of their own and are homed through their children.
